# Working With Claude Code

How this vault gets used as the brain of the build, rather than as documentation
nobody opens.

## The core problem

**Claude Code reads files, not graphs.** Every `[[wikilink]]` in this vault is
invisible to it — `[[Risk Envelope]]` is a string, not an edge. The vault's most
valuable property, its link structure, is the one part a coding agent cannot
traverse natively.

And 57,000 words will not fit in a context window. Loading the vault wholesale is
exactly the *context rot* failure that [[MCP Gateway]] was designed to prevent —
the model gets everything and attends to nothing.

So the vault has to be made **mechanically walkable** and **read in slices**.

## Four mechanisms

### 1. `CLAUDE.md` routes, it does not contain

The repo-root `CLAUDE.md` loads automatically into every session. It holds a
routing table — *building an agent? read that agent's note and nothing else* —
plus the [[Safety Invariants|hard rules]] that constrain code written before
anyone thinks to open a note.

It stays short on purpose. It is the index card, not the library.

### 2. Wikilinks resolve through [[Vault Map]]

[[Vault Map]] is generated by `scripts/build_vault_map.py`: a name → path table
for all 91 notes. Note names are unique, so `Glob **/Risk Envelope.md` also
works. Either way a coding agent that meets a link while reading can follow it.

Re-run the script after adding, renaming, or moving a note. It also reports name
collisions, which would make a wikilink ambiguous.

### 3. Bidirectional binding — spec ↔ code

Inherited from [[Repo — jarvis]]'s spec-file discipline, which is the practice
that shaped this vault. See [[Conventions]].

Every buildable note carries:

```yaml
status: spec | building | built
implemented_by: [src/genesis/agents/screener.py]
```

Every source file opens with the reverse:

```python
# Spec: Genesis Markdown/20-Agents/Research/Agent — Screener.md
```

This is what turns the vault from static documentation into a **live build
tracker**. The Dataview query at the bottom of [[Vault Map]] shows what is spec,
what is in flight, and what is done — without reading any code.

The rule that makes it hold: **code and spec disagree → the spec changes first,
deliberately, in the same commit.** A spec that lies is worse than no spec,
because it is trusted.

### 4. Subagents keep exploration out of the main context

| Agent | Use for |
|---|---|
| `vault-librarian` | *"What does the design say about order rejection?"* — reads across notes, returns ~300 cited words |
| `trading-researcher` | *"How does freqtrade guard drawdown?"* — reads the corpus, returns file citations and snippets |

Both are read-only and both exist for the same reason: the coding conversation
needs its context for code. Delegating breadth is not a nicety here — a handful
of unguarded vault reads will crowd out the file you are actually writing.

## Commands

| Command | Does |
|---|---|
| `/spec <note>` | Loads a component's note plus its one-hop links, and summarises interfaces, constraints, acceptance criteria, and dependencies |
| `/impl <note> <paths>` | Verifies acceptance criteria, sets `status`/`implemented_by`, adds the spec pointer, regenerates [[Vault Map]] |

## A session, start to finish

1. Open `~/Projects/Genesis Agent/` in VS Code. `CLAUDE.md` loads itself.
2. Check [[Build Order]] for the current phase.
3. `/spec <component>` to load the design.
4. Ask `trading-researcher` how the corpus solves the hard part.
5. Write the code, with its spec-pointer header.
6. `/impl <component> <paths>` to close the loop.
7. Commit the code **and** the note together.

## What not to do

- **Don't `@`-import the vault into `CLAUDE.md`.** ~75k tokens spent before you
  type anything, and the model attends to none of it.
- **Don't add an Obsidian MCP server.** This is local markdown; Read, Grep and
  Glob already beat it. An MCP hop adds tokens and a failure mode for no gain.
  ([[MCP Server Catalog]] is for *trading* tools.)
- **Don't let the model invent design.** If the vault doesn't specify it, that
  belongs in [[Open Questions]] as a decision — not in the code as a guess.
- **Don't mark something `built` without checking the acceptance criteria.** A
  false `built` stops anyone from looking again.
