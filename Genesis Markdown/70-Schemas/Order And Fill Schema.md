# Order And Fill Schema

The money objects. Append-only in the [[Trade Ledger]]. Every field here exists for a
reason and several exist to catch bugs.

## Proposal

Before an order exists, there is a proposal. It carries no authority.

```yaml
id: ord_prop_01J8XV
created: 2026-08-29T14:31:01Z
created_by: order-manager
trace_id: tr_01J8XP

symbol: NVDA
side: buy
qty_requested: 192
order_type: limit
limit_price: 121.20
stop_price: 118.40
target_price: 124.50
time_in_force: day
bracket: true

origin:
  kind: idea                  # idea | strategy | human | agent
  ref: idea_01J8XS
strategy: nq_orb_v3
account: primary

sizing_detail:                # from [[Agent — Portfolio And Allocation]]
  equity: 100000
  risk_pct: 0.5
  stop_distance: 2.60
  raw_size: 192
  binding_constraint: null

arrival_mid: 121.02           # STAMPED HERE — [[Agent — Execution Quality]] needs it
arrival_ts: 2026-08-29T14:31:01.980Z
```

`arrival_mid` must be captured at proposal time, not looked up afterwards. Slippage
measured against a retrospectively-fetched price is meaningless.

## Approval

Issued by [[Pre-Trade Risk Engine]]. Without one, no order can be placed.

```yaml
approval_id: appr_01J8XV
proposal_id: ord_prop_01J8XV
decision: resize              # approve | resize | reject
approved_qty: 120
binding_check: correlated_exposure
worst_case_loss: 312.00
checks: [...]                 # full check list — see [[Pre-Trade Risk Engine]]
envelope_version: 7
approval_mode: confirm
human_confirmation:
  method: voice               # voice | dashboard | auto
  utterance: "confirm NVDA one twenty"
  at: 2026-08-29T14:31:02Z
expires_at: 2026-08-29T14:32:02Z
signature: <hmac>
```

Single-use, short-lived, bound to the exact order, signed
([[genesis-execution-mcp]]).

## The `client_order_id`

Format: `gen_{YYYYMMDD}_{HHMMSS}_{SYMBOL}_{side}_{seq}`

Generated by Genesis, never by the broker. It is:

- The **idempotency key** — a duplicate placement with the same id is refused
- The **disambiguator** — after a timeout, `query_order(client_order_id)` tells you
  whether the order exists, so retries are safe
- The **join key** across the ledger, the broker, and the [[Episodic Log]]

Never blind-retry a placement. Query by this id first
([[Agent — Order Manager]], [[Error Handling And Degradation]]).

## Required-field invariants

Each of these is a test, not a hope:

| Rule | Enforcement |
|---|---|
| Every order has an `approval_id` | Insert fails without one |
| Every fill has an `approval_id` | Critical alert if absent |
| Approval is unexpired and unused at placement | Server-side check |
| Approval binds to the exact symbol/side/qty/price | Mutation invalidates it |
| Every object has a `trace_id` | Audit chain requirement |
| Prices and fees are `Decimal` | Type test |
| Orders and fills are append-only | Database-level constraint |

## Bracket groups

Entry, stop, and target share a `bracket_group`. The group is the unit — cancelling
the entry cancels the unfilled children; filling the entry activates them.

If the broker lacks native brackets, the group is emulated and
[[Agent — Order Manager]] treats a failure to place the stop as `fatal`, flattening
rather than holding unprotected ([[Agent — Broker Adapter]] capability declaration).
